# Gold-корпус русской лингвистики (v1)

Датасет для benchmark'а локальных LLM: проверяет, умеет ли модель **контекстно**
анализировать русский текст перед синтезом речи и возвращать аннотации, а не
переписанный текст.

## Происхождение

Разметка написана вручную (таблицы в `tools/build_llm_dataset.py`); никакая модель
корпус не порождала — это прямо запрещено постановкой задачи. Границы аннотаций
(`span_start`/`span_end`) вычисляются при сборке по исходной строке, поэтому gold
не может разойтись с текстом; валидатор дополнительно проверяет
`source == target_text[span_start:span_end]`.

## Файлы

| Файл | Что внутри |
|---|---|
| `dataset.v1.jsonl` | сами кейсы, одна строка — один кейс |
| `schema.json` | схема кейса (по ней валидируется корпус) |
| `prompts/analyzer.v1.txt` | версионный prompt (общий с production Analyzer) |
| `expected/analyzer.response.schema.json` | схема ответа модели для Ollama `format` |
| `expected/summary.json` | счётчики и список кейсов на проверку |
| `expected/review.md` | список кейсов для проверки человеком до полного прогона |

## Проверка

```bash
./venv/bin/python tools/build_llm_dataset.py --check   # валидация без записи
./venv/bin/python -m pytest tests/test_llm_benchmark_dataset.py -q
```

## Что проверяет человек перед полным прогоном

Готовый список — в `expected/review.md` (генерируется вместе с корпусом).

1. Кейсы с `ambiguous: true` — согласиться с пометкой или уточнить gold.
2. Спорные ударения и омографы: `expected[].meaning` должен описывать то значение,
   которое действительно подразумевает контекст.
3. Латиница и аббревиатуры: `suggested_form` — это **предложение** произношения,
   а не обязательная норма (`needs_review: true`).
