# Вкладка «Сам себе звукорежиссер» (запись диалога с микрофона)

Режим, в котором диалог озвучивает **сам пользователь** (или несколько людей):
каждая роль записывается с микрофона браузера, приложение хранит дубли, делает
минимальную обработку, восстанавливает исходный порядок реплик и собирает один
файл. Страница описывает назначение вкладки, порядок обработки, схему хранилища
`recordings/`, ограничения режима и автоматические тесты, подтверждающие результат.

**Финальный результат режима — единый MP3-файл с цельным диалогом**, собранным из
записанных пользователем реплик двух или трёх голосов в исходном порядке диалога.
Отдельные WAV/raw/processed/take-файлы — внутренние рабочие материалы, а не
результат. Мастер собирается в PCM, и MP3 кодируется **один раз** из финального
мастера (многократное MP3 → decode → MP3 запрещено).

## Workflow

```text
текст диалога → разбор существующим парсером → роли
→ назначение записываемых голосов → запись реплик (по диалогу или по ролям)
→ выбор лучших дублей → минимальная обработка (скорость, высота, очистка)
→ монтаж в исходном порядке + паузы + LUFS + лимитер → один MP3
```

## Возможности

- **Разбор диалога по ролям** — тем же `dialogue_parser.py` (`Спикер: реплика`,
  маркеры `(N)`); своего парсера у режима нет.
- **Запись по порядку диалога и по ролям** — переключатель только меняет порядок
  показа. Порядок монтажа всегда определяется `index` реплики: записали всю роль
  Анны, потом всю роль Игоря — в файле всё равно `Анна → Игорь → Анна → …`.
- **Записываемые голоса** (`RecordedVoiceProfile`) — отдельная сущность от
  TTS-голоса: имя и настройки обработки. Один голос можно назначить нескольким
  ролям; сырые записи в `voices/` не попадают и в модели не уходят.
- **Несколько дублей на реплику.** Повторная запись не перезаписывает прежнюю:
  дубли можно слушать, выбирать активный, удалять. Если удалить активный,
  активным становится последний оставшийся, а если дублей не осталось — реплика
  снова считается незаписанной.
- **Минимальная обработка** на записываемый голос: скорость (`0.75–1.25` в UI),
  высота (`−6…+6` полутонов) и очистка от постоянного фонового шума
  (DeepFilterNet, если установлен).
- **Неразрушающая обработка.** Хранятся сырая запись и настройки; обработанная
  версия — кэш. Любая правка считается от raw, поэтому повторные изменения не
  накапливают артефакты.
- **Один внутренний формат.** Любая запись приводится к WAV, моно, 24 кГц — тому
  же `SAMPLE_RATE`, что у остального пайплайна: браузерные 48 кГц и стерео
  ресемплируются и сводятся в моно. Без этого длительность дубля, темп и паузы
  отличались бы от слышимых ровно во столько раз, во сколько отличается частота.
- **Превью обработки** — «Прослушать обработку» для активного дубля, без
  пересчёта всех реплик при движении ползунка.
- **Монтаж.** Пауза `pause_ms` вставляется между репликами, тишина на краях
  записей срезается, затем применяются существующие финальные проходы проекта:
  LUFS-нормализация и лимитер. Кроссфейда между репликами нет: сшивка идёт по
  сэмплам, пауза — цифровая тишина, поэтому атака следующей реплики не съедается
  (существующий `cross_fade_duration` — внутренняя ручка F5 для сшивания кусков
  одной реплики, на таймлайне диалога он не применяется).
- **Сохранение проекта.** Состояние лежит на backend (`recordings/{project_id}/`)
  и переживает перезагрузку страницы: дубли, назначения голосов, настройки
  обработки и порядок записи.

## Порядок обработки и монтажа

Обработка дубля — единый неразрушающий конвейер `recording_audio.process`, порядок
шагов зафиксирован:

```text
сырая запись
→ decode / resample / mono (WAV, 24 кГц)
→ denoise (только если включён в профиле голоса)
→ edge silence trim
→ time-stretch (скорость без изменения высоты)
→ pitch shift (высота без изменения длительности)
→ gain / peak safety
→ обработанный дубль
```

Почему именно так:

- **Обрезка краёв — до растяжения.** После time-stretch границы речи размываются,
  и срезать тишину по ним уже нельзя.
- **Уровень — последним.** Он зависит от результата всех предыдущих шагов;
  выравнивание — мягкое, а итоговая воспринимаемая громкость всё равно
  контролируется финальным проходом.
- **Time-stretch — phase vocoder** `librosa.effects.time_stretch`, без обычного
  resample (тот менял бы и длительность, и высоту). При `speed = 1.0` librosa не
  вызывается вовсе.
- **Очистка необязательна.** Если DeepFilterNet не установлен или падает, запись
  обрабатывается без очистки, а причина попадает в предупреждения.

Монтаж (`recording_pipeline.assemble`) поверх готовых дублей:

```text
обработанные дубли → паузы между репликами → PCM/WAV-мастер
→ LUFS-нормализация всего трека → лимитер → один MP3
```

- **Паузы.** `pause_ms` вставляется **между** репликами и только между ними: перед
  первой репликой пауза не добавляется, а тишина внутри записей уже срезана
  обрезкой краёв, поэтому реальный зазор равен `pause_ms`, а не «тишина записи +
  пауза». Значение берётся из настроек сборки проекта, по умолчанию
  `DEFAULT_PAUSE_MS` (400 мс); индивидуальной паузы на реплику нет.
- **LUFS и лимитер — по всему диалогу.** Финальный проход
  `audio_pipeline._finalize_track` применяется к собранному диалогу целиком, а не к
  каждой роли отдельно: воспринимаемая громкость контролируется один раз по всему
  треку.
- **Один MP3.** Внутренний мастер сохраняется как `dialogue-master.wav`, финальный
  файл — `dialogue.mp3` (`TTS_RECORDING_FORMAT`, по умолчанию `mp3`); MP3
  кодируется один раз из мастера.
- **Блокировка.** Пока есть незаписанные реплики, `POST …/render` отвечает **409**
  со списком `missing`: диалог собирается только целиком. Монтаж идёт в отдельном
  потоке, запуск объявляется до ухода в поток, поэтому `render/status` не отдаёт
  результат прошлого монтажа; повторный запуск во время сборки — тоже 409.

## Хранилище `recordings/`

```text
recordings/
  projects.json                  индекс: id → имя, статус, время, сколько записано
  {project_id}/
    project.json                 полное состояние проекта
    raw/                         сырые дубли (не изменяются никогда)
    processed/                   кэш обработанных версий (по ключу настроек)
    previews/                    временные превью обработки
    output/                      dialogue-master.wav + dialogue.mp3
```

`project.json` содержит: `id`, `name`, `dialogue_text`, `status`, `created_at`,
`updated_at`, `last_error`; `replicas[]` — `{index, speaker, text}` из общего
парсера в исходном порядке; `role_voices` — `{speaker: profile_id}`;
`voice_profiles[]` — `{id, name, speed, pitch_semitones, denoise, created_at}`;
`takes[]` — `{id, replica_index, voice_profile_id, raw_file, duration_sec,
created_at, level_warning}`; `active_takes` — `{replica_index: take_id}` (решение
пользователя, а не свойство файла); `recording_order` — `dialogue` или `roles`;
`render_settings` — например `pause_ms`.

Запись JSON атомарна (временный файл → `os.replace`), все имена файлов
генерируются хранилищем: пользовательское имя роли в путь не попадает никогда.
Сырой дубль получает имя вида `r0001_take01.wav`, а файл обработанной версии —
суффикс с ключом настроек, поэтому другая скорость или высота даёт другой файл и
обработка «поверх уже обработанного» не выполняется. Сырые записи не попадают в
`voices/` и не уходят в F5/XTTS.

## Ограничения режима

Первая версия сознательно узкая: нет drag-and-drop таймлайна, многодорожечного
редактора, EQ, компрессора, реверба, ручного редактирования waveform и живой
записи нескольких участников одновременно. Гибридный режим (часть ролей — живая
запись, часть — TTS) не реализован, но хранилище спроектировано так, чтобы его
можно было добавить: активный дубль реплики — отдельная сущность, а сборка
принимает готовый waveform.

- **Кроссфейда между репликами нет.** Реплики сшиваются по сэмплам после обрезки
  краёв, пауза — цифровая тишина. Переиспользовать на таймлайне нечего:
  `cross_fade_duration` — внутренняя ручка F5 для сшивания кусков одной реплики
  внутри движка, а не overlap на таймлайне.
- **Реальный микрофон не проверялся.** Запись с живого устройства (выбор входа,
  отказ доступа `NotAllowedError`, отсутствие устройства `NotFoundError`,
  level meter, обратный отсчёт) подтверждена только чтением кода; автотесты
  работают на подготовленных аудиофайлах. Ручной сценарий с записью двух ролей
  голосом **не выполнялся**.
- **Пауза — общая** для всего диалога: индивидуальной паузы на реплику в этой
  версии нет.
- **Формат финального файла зафиксирован** (`mp3`): задача режима — единый MP3,
  поэтому в панели «Монтаж» выбор формата фактически один.
- **Denoise ограничен.** DeepFilterNet уменьшает постоянный шум и гул, но не
  удаляет речь других людей и громкие отдельные звуки.
- **Диапазоны ручек в UI уже backend'а.** Ползунки дают `0.75–1.25` и `−6…+6`
  полутонов; backend принимает `0.5–2.0` (`RECORDING_SPEED_RANGE`) и `−12…+12`
  (`RECORDING_PITCH_RANGE`), чтобы API и профиль, сохранённый не из интерфейса, не
  упирались в потолок UI.
- **Обработка последовательная.** Монтаж идёт в одном потоке, без параллельного
  DSP по репликам; прогресс читается опросом `render/status`.
- **Ограничения загрузки.** Один дубль — не длиннее `TTS_RECORDING_MAX_SEC`
  (по умолчанию 300 с) и не больше `TTS_RECORDING_MAX_BYTES` (64 МБ); формат
  проверяется успешностью декодирования, расширение — только грубый фильтр.

## Тесты

Результат режима подтверждают автоматические тесты на подготовленных
fixture-аудиофайлах (реального микрофона в агентской среде нет):

| Файл | Тестов | Что проверяет |
|---|---|---|
| `tests/test_recording_store.py` | 8 | хранилище: проекты, роли, дубли, активный дубль, атомарность |
| `tests/test_recording_audio.py` | 14 | декод в моно/24 кГц, time-stretch, pitch, denoise, trim, уровень |
| `tests/test_recording_api.py` | 10 | эндпоинты `/api/recording-projects…`, превью, рендер |
| `tests/test_recording_pipeline.py` | 11 | интеграционные Test A–G, Test I и 3 регресса на запуск монтажа |

Интеграционные сценарии (`test_recording_pipeline.py`):

- **Test A** — цельный диалог на двух голосах: порядок `A→B→A→B` по доминирующей
  частоте сегментов, паузы, один MP3.
- **Test B/C** — три голоса и запись блоками по ролям: монтаж восстанавливает
  исходный порядок `A→B→C→A→B→C`.
- **Test D** — обработка голосов: скорость и высота применяются только к своим
  голосам.
- **Test E** — смена дубля: следующий рендер использует новый дубль.
- **Test F** — незаписанная реплика: 409 с её индексом, файла не появляется.
- **Test G** — декод MP3: контейнер, каналы, частота, длительность, сэмплы.
- **Test I** — финальный проход (LUFS + лимитер) по всему диалогу.

Полный прогон на момент уборки документации: **1320 passed** (включая 32 проверки ссылок в
документации), падений и пропусков нет;
recording-набор отдельно — **43 теста**. Реальный микрофонный E2E —
`REAL MICROPHONE E2E: NOT VERIFIED`.
