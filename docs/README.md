# Документация VOICE_SYNTEZ

Страницы описывают **текущее состояние кода**, а не историю планов. Если поведение в документе
расходится с кодом — прав код: поправьте документ.

## С чего начать

- Впервые запускаете — [`install.md`](install.md), затем [`guide-tabs.md`](guide-tabs.md).
- Пишете интеграцию — [`api.md`](api.md).
- Разбираетесь, как всё устроено внутри — [`architecture.md`](architecture.md).
- Что-то сломалось — [`operations.md`](operations.md) и [`known-issues.md`](known-issues.md).
- Хотите понять, откуда взялась подсистема — [`history.md`](history.md).

## Соглашения по документации

- Язык — русский, как и комментарии в коде.
- Команды и примеры должны запускаться как написано: `./venv/bin/python ...` из корня проекта.
- Числа (пороги, лимиты, размеры) берутся из `backend/config.py`, а не из памяти.
- Исторические планы и отчёты по фазам в репозитории не хранятся: их содержание перенесено сюда,
  а полные тексты остались в истории git (см. [`history.md`](history.md)). Исключение — `reports/`:
  там лежат рабочие тексты незакрытой работы (полный аудит и план исправлений), пока находки не
  разобраны; в `docs/` они не переносятся, потому что описывают не текущее состояние кода.
