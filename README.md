# TTS-дашборд: озвучка русских диалогов

Локальное веб-приложение: вставляете диалог в формате `Спикер: реплика`, назначаете каждому
спикеру голос (клонируется из вашего reference-аудио) и параметры речи — на выходе один готовый
аудиофайл со всем диалогом. Второй режим — **«Сплошной текст»**: загрузка `.txt`/`.md` и озвучка
одним голосом, без спикеров и маркеров. Третий — **«Сам себе звукорежиссер»**: диалог
озвучивается не моделью, а вами с микрофона, и собирается в один MP3.

Всё работает офлайн; интернет нужен только для установки зависимостей и загрузки весов моделей.

## Возможности

| Вкладка | Что делает |
|---|---|
| `01` **Голоса** | Библиотека голосов: клонирование из reference-аудио, проверка качества записи (пол, перегрузка, полоса), сравнение голоса на разных движках, эмоции и интонационные профили |
| `02` **Озвучка диалога** | Разбор диалога по спикерам, назначение голосов, варианты (take'ы) реплик, проверка качества синтеза, таймлайн, рендер целиком, экспорт и импорт проекта |
| `03` **Сплошной текст** | Озвучка целого `.txt`/`.md` одним голосом + панель «Предложения для словаря» |
| `04` **Сам себе звукорежиссер** | Запись реплик диалога с микрофона браузера: роли, дубли, минимальная обработка, сборка в исходном порядке → один MP3 |
| `05` **Словарь** | Правила произношения: ударения и «ё», приоритет над автоматом, предпросмотр «что услышит модель» |
| `06` **Модели** | Веса на диске: скачать, удалить, выгрузить из памяти, очистить кеш приложения |

Сброс вкладки (только кеш или полный, вместе с открытым проектом) — панель «Сброс» на вкладках
`02` и `03`.

Движок выбирается **для каждого голоса отдельно**, а не глобально: в одном диалоге можно смешивать
F5-TTS, XTTS, Qwen3-TTS и Kokoro-ru. Поддерживаются `f5` (F5-TTS Russian, ударения, по умолчанию),
`xtts` (XTTS v2), `xtts-banana` (русский файнтюн), `qwen3-tts` (Qwen3-TTS 1.7B, необязательный пакет
и веса ~4.5 ГБ) и `kokoro-ru` (пресетный черновой движок: свои встроенные голоса вместо клонирования,
веса ~0.7 ГБ — карточки «Света», «Дима» и «Маша» появляются в «Моих голосах» сами, как только веса
скачаны). У движка есть режимы работы — черновик, качество, эксперимент — а у движка, чьи
веса не скачаны, объявлен откат на F5, чтобы диалог не падал. Подробности —
в [`docs/install.md`](docs/install.md) и [`docs/synthesis.md`](docs/synthesis.md).

## Требования

- macOS на Apple Silicon (M1/M2/M3), ≥ 16 ГБ ОЗУ. Поднятые движки остаются в памяти: F5-TTS ~1.4 ГБ,
  XTTS базовая ~1.9 ГБ, banana-файнтюн ~5.2 ГБ (набор «F5 + обе XTTS» — порядка 9 ГБ), Qwen3-TTS
  ~4.5 ГБ плюс ~0.4 ГБ её токенизатора, Kokoro-ru ~0.7 ГБ.
- Python 3.11 (`brew install python@3.11`)
- ffmpeg (`brew install ffmpeg`) — нужен для MP3 и m4a/mp3-референсов

## Установка

```bash
python3.11 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Веса моделей скачиваются отдельно: F5-TTS — сам при первом старте, остальные — кнопкой «Скачать»
во вкладке `06` «Модели». Полная инструкция, ручная загрузка весов, опциональный DeepFilterNet
(очистка шумных референсов) и необязательный движок Qwen3-TTS — в [`docs/install.md`](docs/install.md).

## Запуск

Самый простой способ — **двойной клик по `VOICE_SYNTEZ.command`** в Finder (то же самое:
`bash VOICE_SYNTEZ.command`). Лаунчер сам находит Python 3.11+, при необходимости создаёт `venv`,
ставит зависимости, поднимает backend на свободном порту начиная с 8000 и открывает браузер.

```bash
bash VOICE_SYNTEZ.command      # лаунчер: venv, зависимости, сервер, браузер
./run.sh                       # старый способ (venv уже активирован)
```

| Что | Где |
|---|---|
| Адрес по умолчанию | <http://127.0.0.1:8000> (занят — лаунчер возьмёт следующий свободный) |
| Лог | `logs/voice_syntez.log` |
| Остановка | `Ctrl+C` в окне лаунчера |
| Второй экземпляр | запрещён: замок `.voice_syntez.lock`, повторный запуск просто откроет браузер |
| Проверка окружения | `./venv/bin/python tools/doctor.py` — версия Python, зависимости, ffmpeg, веса, права, порт |

Модель грузится в фоне при старте (~15 с на MPS); индикатор в шапке дашборда показывает готовность.
Подробности про порты, логи и устройство лаунчера — в [`docs/install.md`](docs/install.md).

## Первый сценарий: диалог за пять шагов

1. **Голоса** — создайте голос из записи 6–15 с (или запишите прямо в браузере) и проверьте бейджи
   качества. Голос можно позже перевести на другой движок, не теряя референс.
2. **Озвучка диалога** — вставьте текст вида `Анна: Привет!`, нажмите «Разобрать», назначьте
   голоса спикерам и при необходимости задайте паузы и громкость.
3. **Подготовка** — обязательный проход: нормализация текста, «ё», словарь, ударения. Если включён
   локальный LLM-анализатор — ещё и подсказки по интонации.
4. **Рендер** — «Озвучить диалог». Реплики синтезируются по очереди, у каждой можно сравнить
   варианты и оставить лучший; таймлайн показывает, где что звучит.
5. **Экспорт** — скачать готовый файл, выгрузить `.ttsproject` (проект с аудио) или отдельные
   дорожки и субтитры.

Пошаговое описание интерфейса со всеми кнопками — в [`docs/guide-tabs.md`](docs/guide-tabs.md).

## Где лежат данные

| Путь | Что там |
|---|---|
| `data/voice_syntez.db` | проекты, реплики, take'ы, правила словаря (SQLite) |
| `voices/` | reference-аудио и `voices.json` — библиотека голосов |
| `output/` | готовые файлы; `output/projects/{id}/` — куски проектов |
| `recordings/` | проекты вкладки «Сам себе звукорежиссер»: сырые дубли, обработанные версии, готовый MP3 |
| `models/` | веса F5-TTS, XTTS, Qwen3-TTS и Kokoro-ru (в git не попадают) |
| `benchmarks/` | корпуса и результаты прогонов LLM-анализатора и переноса просодии |
| `logs/` | журнал backend |

Все перечисленные каталоги, кроме `benchmarks/`, — рабочее состояние пользователя и в git не
попадают.

## Тесты

```bash
./venv/bin/python -m pytest -q      # модели не поднимаются: движок-заглушка
```

Реальные модели и живой сервис для pytest не нужны — тесты идут на заглушках и синтетическом
аудио. Что именно проверяется, как гонять отдельные наборы и чем отличаются real-model прогоны —
в [`docs/testing.md`](docs/testing.md).

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| `ffmpeg не найден` | `brew install ffmpeg` — без него не работает MP3 |
| Порт занят | ничего: лаунчер сам выберет свободный, либо `PORT=8010 bash VOICE_SYNTEZ.command` |
| «Приложение уже запущено» | открыть <http://127.0.0.1:8000>; второй экземпляр не поднимается намеренно |
| Модель не поднимается | `./venv/bin/python tools/doctor.py` — покажет, каких весов не хватает |
| Не хватает памяти | выгрузить лишний движок во вкладке `06` «Модели»; держите один движок вместо трёх |
| Тумблер очистки записи погашен | DeepFilterNet не установлен: `pip install --no-deps -r requirements-denoise.txt` |

Больше диагностики — в [`docs/operations.md`](docs/operations.md) и
[`docs/known-issues.md`](docs/known-issues.md).

## Структура репозитория

```text
backend/          FastAPI-приложение: движки, пайплайн синтеза, БД, очередь, ресурсы
frontend/         дашборд без сборки: index.html + app.js + style.css
tools/            вспомогательные скрипты: doctor, benchmark'и, генератор корпуса, диагностика
tests/            pytest: модели не поднимаются, движок-заглушка
benchmarks/       gold-корпус LLM-анализатора и корпус переноса просодии
docs/             документация: руководство, API, архитектура, эксплуатация
models/ voices/ output/ recordings/ data/ logs/   рабочие каталоги (в git не попадают)
VOICE_SYNTEZ.command   лаунчер для macOS
```

Разбор слоёв, воркеров и схемы БД — в [`docs/architecture.md`](docs/architecture.md).
