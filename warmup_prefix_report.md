## 2. Архитектурное решение

Прогрев встроен **в синтез одной реплики**, а не в сборку трека: решение о префиксе
принимается на уровне куска, там же ищется граница цели и там же выполняется откат.
Логика разделена на два слоя:

* `backend/warmup_context.py` — «нужен ли прогрев», «какой текст префикса», «где
  начинается цель», кэш и валидация. Модуль не знает ни про движки, ни про
  постобработку, поэтому тестируется без моделей;
* `backend/audio_pipeline.py` — вызов движка, обрезка по найденной границе и
  существующая постобработка (края → RMS/gain/pitch), затем QA.

Прогрев и контекстный план короткого слоя — два ответа на одну проблему, поэтому при
применённом префиксе контекстный план не строится: иначе в модель ушли бы и префикс, и
соседняя реплика, а обрезать пришлось бы дважды.

`text_preprocess.py` не тронут: LLM-логика в детерминированный шаг нормализации не
попадает (§4). Публичный интерфейс `SynthesisEngine` тоже не менялся; код синтеза не
дублируется — обе ветки (с прогревом и без) идут через один `_synthesize_chunk`.

## 3. LLM backend

Существующий: **Ollama** через `backend/llm/ollama_client.py` и singleton
`backend/llm/analyzer.py` (модель выбирается тем же `selected_model()`, что и
лингвистический анализ, — primary с откатом на fallback). Отдельная модель для
прогрева не заводится.

* запрос структурированный: JSON-схема `{"prefix": string}`
  (`warmup_context.RESPONSE_SCHEMA`), потому что клиент по умолчанию просит
  структурированный ответ, и «просто текст» разбирался бы догадками;
* параметры консервативные: `temperature=0.3`, `seed=0`, `num_predict=96`,
  `num_ctx=2048`, `keep_alive=5m`, `think=False`,
  `timeout=TTS_WARMUP_LLM_TIMEOUT_SEC`;
* промпт версионирован (`warmup_context.PROMPT_VERSION = "1"`), версия входит в ключ
  кэша;
* пользовательский диалог в INFO-лог не пишется: логируются длины, границы и причины
  (`warmup enabled/generated/aligned/fallback`), полный префикс — только в метаданных
  варианта (для диагностики).

## 4. Alignment-механизм

Выбран **уже имеющийся** ASR с таймстемпами слов: `transcribe.transcribe_words`
(Whisper large-v3-turbo, отдельный процесс, режим `--words`). Новая зависимость не
добавлена (§10, §26).

`locate_target_start(audio, sample_rate, full_text, target_text)` ищет слова цели как
подпоследовательность распознанного текста **с конца** (цель — суффикс синтез-текста,
поэтому такое же слово внутри префикса не может быть принято за начало цели) и
возвращает `TargetBoundary(start_sec, confidence, method, matched_words, total_words)`.
Порог уверенности — `TTS_WARMUP_ALIGNMENT_MIN_CONFIDENCE` (по умолчанию 0.8: та же
граница, что у обрезки контекста коротких реплик, — второй порог для той же задачи
разошёлся бы с первым). К началу цели добавляется запас `TTS_WARMUP_PREROLL_MS`
(30 мс), чтобы не срезать атаку первого фонема.

Запрещённые способы (доля символов, расчётная длительность, фиксированный offset) не
используются нигде.

## 5. Fallback

Откат к обычному синтезу цели — обязательное поведение, а не «на всякий случай»:

| Событие | Что происходит |
|---|---|
| `TTS_WARMUP_ENABLED=0` или `warmup=false` в задаче | прогрев не запрашивается |
| движок не в `TTS_WARMUP_ENGINES` | прогрев не запрашивается |
| цель длиннее порогов | прогрев не запрашивается |
| LLM недоступна / нет модели | синтез цели без прогрева, причина в логе |
| таймаут или исключение LLM | то же |
| пустой ответ, разметка, повтор цели, слишком длинный префикс | префикс отброшен, синтез цели |
| критическое состояние памяти | прогрев пропускается (`REASON_MEMORY`) |
| граница цели не найдена или уверенность ниже порога | **повторный синтез только цели**, `warmup_fallback = alignment_failed` |

Ни одно из событий не переводит задачу в `error`: прогресс, статус и готовый файл
формируются так же, как без прогрева.

## 6. Новые переменные окружения

`TTS_WARMUP_ENABLED` (0), `TTS_WARMUP_MAX_CHARS` (80), `TTS_WARMUP_MAX_WORDS` (12),
`TTS_WARMUP_MAX_PREFIX_CHARS` (180), `TTS_WARMUP_LLM_TIMEOUT_SEC` (10),
`TTS_WARMUP_MAX_TOKENS` (96), `TTS_WARMUP_TEMPERATURE` (0.3),
`TTS_WARMUP_NUM_CTX` (2048), `TTS_WARMUP_KEEP_ALIVE` (5m),
`TTS_WARMUP_ALIGNMENT_MIN_CONFIDENCE` (0.8), `TTS_WARMUP_PREROLL_MS` (30),
`TTS_WARMUP_CACHE_SIZE` (256), `TTS_WARMUP_ENGINES` (f5).

Все описаны в README. Порог уверенности взят из уже измеренной границы короткого слоя,
запас 30 мс — из требования §9, остальное консервативно.

## 8. A/B smoke на живой модели

**Не выполнен.** Причина не в коде: на машине уже загружена модель Ollama `qwen3:8b`
(5.2 ГБ), состояние памяти — `warning`, система занята на ~85 %, а F5-TTS добавляет ещё
3–4 ГБ. Одновременная загрузка LLM и TTS упирается в тот самый memory guard, который
защищает приложение от свапа, — и это ровно то поведение, которое прогрев обязан
уважать (при критической памяти он пропускается, `REASON_MEMORY`).

Команды для прогона (сначала освободить память, затем A и B):

```bash
# 1) освободить LLM перед рендером
ollama stop qwen3:8b
# при нехватке памяти взять лёгкую модель: анализатор и прогрев используют одну и ту
# же Ollama, поэтому выбор модели — LLM_FALLBACK_MODEL=...q4_K_M

# 2) A: обычный синтез первых 10 фраз корпуса §23
TTS_SYNTHESIS_TRACE=1 ./venv/bin/python tools/short_trace.py \
    --voice <id> --text tests/fixtures/short_corpus_ru.txt --asr --limit 10 \
    --out /tmp/warmup-a.json

# 3) B: тот же набор с прогревом
TTS_SYNTHESIS_TRACE=1 ./venv/bin/python tools/short_trace.py \
    --voice <id> --text tests/fixtures/short_corpus_ru.txt --warmup --asr --limit 10 \
    --out /tmp/warmup-b.json
```

Сравнивать нужно: сохранность первого слова (`asr_final.first_word_ok`), отсутствие
хвоста префикса (в финальном ASR не должно быть слов префикса), WER, длительность,
время и число откатов (`warmup_fallback`). Отдельно для F5, XTTS и XTTS-banana.
**До этого прогона прогрев выключен по умолчанию**, а allowlist содержит только F5 —
включать движок «потому что работает» запрещено (§23).

## 9. Известные ограничения

1. **A/B не проведён** (см. §8) — поэтому `TTS_WARMUP_ENABLED=0`.
1a. **Проверка памяти перед прогревом** смотрит `memory_state() == critical`, а не
   решение тяжёлого планировщика: во время рендера слот занят самим синтезом
   (`HEAVY_TTS`), поэтому «не allowed» означало бы «прогрев не работает при рендере
   никогда». Дефект найден тестами субагента (поле `must_abort`, которое читал
   прежний код, в решении планировщика не существует) и исправлен здесь.
2. **A/B требует двух запусков** (`tools/short_trace.py --warmup` против запуска без
   флага): иначе сравнивать нечего — это свойство измерения, а не ограничение кода.
3. **Пересинтез одной реплики не знает соседей** (в задаче только эта реплика),
   поэтому префикс строится без `previous`/`next`. Кэш по ключу (движок, цель,
   prompt) повторный вызов всё равно снимает.
4. **Метаданные прогрева пишутся в вариант рендера**; для варианта пересинтеза
   пишется только факт применения — возврат `synthesize_replica` не расширялся, чтобы
   не менять существующий контракт очереди.
5. **Прогрев и контекстный план короткого слоя не совмещаются** (одно улучшение на
   реплику: при применённом префиксе контекст не строится).
6. **Whisper поднимается на каждую короткую реплику с прогревом** — вторая статья
   расходов после LLM.
7. **Сплошной текст (`/api/render-text`) прогрева не получает** — выключено явно, без
   отдельного измерения (§20).

## 10. Backward compatibility

* Публичные API не менялись: `warmup_short_replicas` — **новое необязательное** поле;
  без него используется сохранённое значение проекта, затем политика приложения.
* Формат `dialogue_text` не менялся; прогрев не становится репликой парсера.
* `RenderSettings.warmup = None` — прежнее поведение для всех существующих вызовов;
  `RenderResult.warmups` — новое поле с пустым значением по умолчанию.
* Существующие тесты и семантика QA, вариантов и пересинтеза для реплик без прогрева
  не менялись.

## 11. Соответствие acceptance criteria (§25)

| Критерий | Статус |
|---|---|
| короткая реплика синтезируется с LLM-prefix | да (unit + pipeline-тесты; живой прогон — §8) |
| исходный текст не изменяется | да (префикс живёт только в runtime) |
| prefix никогда не слышен в итоговом файле | да при найденной границе; иначе — откат без прогрева |
| начало первого слова не обрезается | запас `TTS_WARMUP_PREROLL_MS`, граница по началу первого слова |
| сомнительная граница → clean fallback | да (`REASON_ALIGNMENT`, повторный синтез цели) |
| ошибка LLM не роняет job | да (все ветки возвращают контекст без префикса) |
| QA проверяет только target | да (QA идёт по подготовленному target-аудио) |
| QA retry заново определяет boundary | да (граница считается в каждой попытке) |
| regenerate работает | да (`synthesize_replica` строит прогрев сам) |
| variants содержат только target audio | да (в вариант уходит обрезанное аудио) |
| F5 и XTTS получают корректный preprocessing | да (`_text_for_engine` + `supports_accents`) |
| можно отключить глобально | да (`TTS_WARMUP_ENABLED=0`) |
| можно отключить для движка | да (`TTS_WARMUP_ENGINES`) |
| можно отключить для задачи | да (`warmup_short_replicas=false`) |
| существующие тесты не сломаны | да (полный прогон: unknown) |
| новые тесты без реальных моделей | да (StubEngine + подставной LLM-клиент) |
| README обновлён | да |
| A/B на реальном F5 до включения по умолчанию | **не выполнен** (§8): функция выключена по умолчанию |
